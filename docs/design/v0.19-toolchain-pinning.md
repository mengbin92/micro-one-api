# 工具链版本固定（v0.19 P2.1）

> 状态：✅ 已落地（2026-08-13）
> 目标：同一 Git SHA 在任何日期、任何环境构建/生成/扫描的结果一致，消除 `go install ...@latest` 造成的隐式漂移。

## 问题背景

v0.19 之前，以下位置直接使用 `@latest`：

- `Makefile init`：`buf`、`wire`
- `Makefile security-*` 与 `.github/workflows/security.yml`：`gosec`、`govulncheck`、`gitleaks`、`syft`、`go-licenses`

风险：同一 commit 在不同日期 clone 后，工具版本不同，导致生成代码、安全扫描结果、SBOM 内容不可复现；本地与 CI 也可能装到不同版本。

## 版本源机制

**`scripts/tool-versions.env` 是唯一版本事实源**（KEY=VALUE 格式，可被 Make 与 shell 同时解析）：

| 变量 | 工具 | 模块 | 固定版本 |
|---|---|---|---|
| `BUF_VERSION` | buf | `github.com/bufbuild/buf` | v1.72.0 |
| `WIRE_VERSION` | wire | `github.com/google/wire` | v0.7.0 |
| `GOSEC_VERSION` | gosec | `github.com/securego/gosec/v2` | v2.28.0 |
| `GOVULNCHECK_VERSION` | govulncheck | `golang.org/x/vuln` | v1.6.0 |
| `GITLEAKS_VERSION` | gitleaks | `github.com/zricethezav/gitleaks/v8` | v8.30.1 |
| `SYFT_VERSION` | syft | `github.com/anchore/syft` | v1.51.0 |
| `GO_LICENSES_VERSION` | go-licenses | `github.com/google/go-licenses` | v1.6.0 |

消费方：

- **本地**：`Makefile` 顶部 `include scripts/tool-versions.env`；`make init` 与 `make security-*` 全部引用 `$(VAR)` 形式。
- **CI**：`.github/workflows/security.yml` 各安装步骤先 `set -a; . scripts/tool-versions.env; set +a` 再 `go install ...@${VAR}`。
- `ci.yml` 的 backend job 本身运行 `make init`，文件缺失会让 make 直接失败，因此该版本文件的存在性天然被门禁覆盖。

其余生成器（`protoc-gen-go`、`protoc-gen-go-grpc`、`protoc-gen-go-http`、`protoc-gen-openapi`）在 `make init` 中本就是精确版本，保持不变。

## 前端 Node 版本

- `web/.nvmrc` 内容为 `24`，与 CI `actions/setup-node` 的 `node-version: '24'` 对齐；
- `web/package.json` 增加 `"engines": { "node": ">=24 <25" }` 作为显式声明；
- 本地使用 nvm/fnm 等工具时 `.nvmrc` 自动生效；npm 版本跟随 Node 分发，不单独固定。

## 升级流程

固定版本不等于不升级——升级必须走**独立 PR**，与功能改动隔离：

1. 只读对比：`make tools-upgrade-check`（逐工具输出 pinned vs latest）。
2. 在 `scripts/tool-versions.env` 中一次性 bump 需要升级的版本（可同批升多个）。
3. 提交为独立 PR，标题如 `chore(toolchain): bump buf to v1.73.0, gosec to v2.29.0`。
4. 若升级涉及 `buf`/`wire` 等生成器，必须本地重跑 `make init && make proto && make wire`，确认 `git status` 无生成漂移，再随 PR 提交。

## 自动化升级策略（Dependabot/Renovate）

当前**未启用**自动化 bot。若后续启用，约束如下（写入 bot 配置而非本文件）：

- 仅允许修改 `scripts/tool-versions.env`（以及必要时 `web/package.json` / `web/.nvmrc`），禁止 bot 直接改写 `Makefile` 或 `.github/workflows/*.yml`；
- 频率限定：每月至多一批；Go 工具与 npm 依赖分组单独 PR；
- 安全相关工具（gosec、govulncheck、gitleaks）可在公告披露关键漏洞时提前升级；
- 升级 PR 必须通过全部 `make verify` 门禁方可合并。

## 验收

- 仓库内不再存在 `go install ...@latest`（`docs/migration/*` 历史迁移计划中的引用属历史文档快照，不视为执行入口）；
- `make init` 与 CI 安装的 Go 工具版本一致；
- `make verify` 全部通过。
