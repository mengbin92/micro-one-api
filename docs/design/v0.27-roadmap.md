## 3. P0 — Executor 第五次 7 天观察闭环

观察数据、固定 PromQL 和事件记录继续以
[`v0.23-executor-observation.md`](./v0.23-executor-observation.md) 为唯一事实源；
本文只管理阶段依赖和最终决策，不复制日检数据。

### 3.1 冻结边界

从 2026-09-01 10:43:15 CST 起保持以下内容不变：

- `relay-gateway` 容器镜像和运行实例；
- `RELAY_ORCHESTRATOR_ENABLED`、allowlist 内容及其 HMAC 密钥；
- 与 canary 直接相关的模型映射、adaptor 和 timeout 配置；
- Prometheus 抓取配置和记录规则。

只允许安全事件或生产事故打断窗口；一旦发生部署、进程重建、指标中断超过既定抓取周期
或 allowlist 变化，立即记中断原因并按观察手册重新建立起点，不拼接两段窗口。

### 3.2 日检与最终决策

每日使用固定 `[24h]` 查询留证，同时保留当前进程累计窗口。最终 PASS 必须同时满足：

- 实际承载 allowlisted 流量的 endpoint / stream 有 orchestrator 样本；
- 成功率不低于同口径 legacy，且没有新增稳定错误类型；
- P95 相对 legacy 回归不超过 20%；
- `quota_error=0`，无重复 Commit、错误 Release、截断流 Commit 或 reservation 卡单；
- failover exhausted 未显著放大，billing / usage log 的 endpoint、stream、渠道和订阅
  来源归因一致。

最终只允许以下两种结论：

- **PASS**：保留旧路径和默认关闭策略，另行审批把 production allowlist 扩到少量明确
  caller；每次只改 allowlist，不同时改代码或计费模式；
- **FAIL**：清空 allowlist 或关闭 flag，记录最小复现和归因，只修复触发失败的边界后
  重启观察；不为赶版本降低准入线。

验收标准：

- [ ] 连续 7×24 小时窗口成立，或 FAIL 后已执行回滚；
- [ ] 观察手册写入最终时间范围、样本、指标和 PASS / FAIL；
- [ ] `docs/design/v0.23-roadmap.md` 的未完成观察项有明确归档结论；
- [ ] 下一步是“有限 allowlist 扩面”或“保持 legacy”，不是直接默认开启或删旧路径。

## 4. P1 — Canonical usage 生产灰度

详细语义、SQL 和回滚规则继续以
[`token-usage-billing-semantics-remediation-2026-08-31.md`](./token-usage-billing-semantics-remediation-2026-08-31.md)
为准。本阶段只执行已经设计并实现的灰度，不重新设计计费模型。

### 4.1 前置条件

- v0.26.3 发布制品完整；
- executor 窗口已 PASS，或已明确回滚到 legacy；
- 生产实际镜像 digest、migration 状态和环境变量已有只读快照；
- billing / log / channel owner schema 已依次应用 `085`–`088`，且三方言 migration
  门禁保持通过；
- 所有 consumer 均支持 v1 双写字段后，才能开启 relay producer gate。

### 4.2 灰度步骤

1. `BILLING_CANONICAL_USAGE_MODE=observe`，producer gate 关闭，验证旧 producer / 新
   consumer 兼容；
2. 小流量开启 `RELAY_CANONICAL_USAGE_PRODUCER`，连续观察至少 48 小时；
3. 用固定 SQL 和指标确认 `ambiguous=0`、`cost_mismatch=0`、unexplained delta=0、
   source / upstream model 覆盖率 100%，且 v1 priced 行没有非法 canonical 静默 fallback；
4. 先对 Kimi / Z.AI / MiniMax 明确范围切 `charge`，一次只扩大一个来源；
5. 小范围 charge 稳定并完成供应商账单抽样对账后，再决定全量；
6. 任一异常先退回 `observe`，additive migration 和历史 canonical ledger 不回滚、不删列。

验收标准：

- [ ] 48 小时 observe 窗口满足设计文档 §12；
- [ ] 小范围 charge 无重复 ledger、余额偏差、来源缺失或价格快照解析失败；
- [ ] Admin 审计页能从一笔 consume 还原五桶、单价、倍率、mode 和 config hash；
- [ ] 回滚演练只切配置即可恢复 observe，未依赖 schema down migration；
- [ ] 全量 charge 是否进入本阶段有书面决策，不以日期替代指标。

## 5. P1 — 历史账务只读审计

历史 ledger 缺少足够协议证据，不能根据 `cache_read_tokens > prompt_tokens` 或
`total_tokens` 数值关系自动退款/追扣。本阶段只补安全的审计入口：

1. 在既有 `scripts/reconcile` 体系中增加只读报告，按 `verified / candidate / unknown`
   分类；
2. 报告列出原 ledger、source、upstream model、usage contract、parse status、五桶成本、
   pricing hash、候选差额和证据来源；
3. 默认不写数据库、不调用 billing RPC；输出确定性 CSV/JSON 供人工与供应商账单核对；
4. 只有 `verified` 且获得显式审批的记录，才在后续独立任务中生成幂等 reversal 草案；
5. 任何冲正都新增 reversal ledger，禁止原地修改 consume ledger；订阅吸收与钱包部分按
   原请求归属分别处理。

验收标准：

- [ ] 默认模式在生产只读账号下可运行，代码路径没有写操作；
- [ ] fixture 覆盖 OpenAI subset、Anthropic exclusive、ambiguous 和证据不足四类；
- [ ] 同一输入重复运行输出稳定，不产生 ledger 或外部副作用；
- [ ] 自动冲正不属于 v0.27.0 发布前置。

## 7. P3 — 触发式事项与明确非目标

| 事项 | 触发条件 |
|------|----------|
| Executor production allowlist 扩面 | 第五次 7 天窗口 PASS，且一次只增加有限明确 caller |
| Executor 默认开启 | production allowlist 再完成独立观察周期；不与 v0.27.0 自动绑定 |
| Responses WebSocket 迁移 | HTTP / SSE production 路径稳定，且 WS 流量与维护成本证明确有收益 |
| 删除 legacy handler | executor 默认开启跨至少两个版本，无回滚依赖和协议缺口 |
| 移除 `PromptExclusive` | 跨至少两个版本 `usage_contract_version=0` 新流量归零 |
| 自动生成或执行历史冲正 | verified 证据、人工审批、幂等 reversal 设计和 dry-run 全部具备 |
| Relay 目录迁移 / Kratos 大仓重构 | 遗留路径已删除，且有明确维护或交付收益 |
| Admin / identity 热点拆分 | 对应子域再次发生实质修改；一次只拆一个域 |

本阶段明确不做：

- 不同时切 executor 路径和 canonical charge；
- 不移动 v0.26.2 / v0.26.3 tag，不在生产服务器构建镜像；
- 不为发布 cache 瞬时故障修改业务代码；
- 不根据模型名或 total 数值关系批量改历史账本；
- 不迁移 Responses WebSocket，不删除 legacy handler，不默认开启 executor；
- 不启动 Relay 全目录搬迁、Kratos v3 或新的微服务拆分。
