# Web 布局方案实施后的代码审查与修复

## 范围

按照桌面上的《Web 页面布局调整方案》审查当前实现，重点覆盖提交 `80a43a3` 引入的布局调整，以及用户仪表盘、管理运营总览、导航、渠道和日志列表的相关组件。审查开始时工作区干净。

原方案中的三列指标、双列图表、告警前置、业务入口压缩和移动筛选面板已实现，本次修复剩余的边界与交互问题。

## 发现与修复

| 优先级 | 发现与根因 | 修复 |
| --- | --- | --- |
| P1 | 运营总览请求失败后，缺失数据被转换成空告警和零值，页面仍显示“运行正常，暂无告警” | 区分失败状态，显示无法确认运行状态的提示和重试按钮；失败时不展示正常状态或默认零值指标 |
| P2 | 1024px 下侧栏占据空间后仍启用三列，长金额被拆成两行 | 三列延后至 xl；较长金额根据卡片可用宽度缩小字号并保持单行，普通值保留大字号 |
| P2 | 1280px 英文运营总览卡片的横向图标与文本布局挤压内容，说明被裁切，金额使用省略号 | 指标值独占一行，图标与标题置于上方；说明可断行，金额不再省略 |
| P2 | 英文快捷操作在四列和手机两列布局中被截断 | 根据空间使用一列、两列和宽屏四列，完整呈现操作名称 |
| P2 | 英文分页在 320px 下使页面宽度达到 353px | 小屏把页码与每页行数放在独立一行，上一页、下一页保持可见；桌面继续横向排列 |
| P2 | 移动抽屉继承普通对话框的高度与滚动方式，长菜单把语言和主题操作挤到屏幕外 | 抽屉使用动态视口高度；固定头部和底部，只让中间菜单滚动 |
| P2 | 消耗排行手写 tab 角色但没有方向键导航，也没有关联 tabpanel | 使用已有 Base UI Tabs 实现焦点管理、方向键、Home/End 和面板关联 |
| P2 | 日志页存在订阅账号筛选，但列表请求、缓存键及后端 ListLogsRequest 均不支持该条件；导出携带参数也不会生效 | 移除无效入口及导出参数，保留后端支持的用户、类型、开始和结束时间筛选；清除操作兼容旧链接中的残留参数 |
| P3 | 订阅套餐页缺失顶栏标题映射，回退为“仪表盘”；公共工具栏清除按钮未本地化 | 补充标题映射，清除按钮走已有翻译层 |
| P3 | 仪表盘加载时仅四张占位卡，加载后变为六张 | 占位卡数量与实际六项指标一致 |

另外处理了长告警消息的换行，避免原始上游标识或错误文本撑出卡片。

## 验证方式

布局回归使用真实浏览器渲染与模拟 API 数据，而非仅断言 CSS 类名。新增 `web/e2e/layout-regression.spec.ts`，检查：

- 中文和英文下的长金额、快捷操作名称完整性。
- 1440、1280、1024、768、390px 仪表盘；列表额外覆盖 320px。
- 有数据的渠道和日志列表、较长名称、分页跳转及页面横向溢出。
- 运营指标卡内容边界、排行键盘导航和关联面板。
- 运营总览请求失败时不显示正常状态，重试成功后恢复。
- 移动导航滚动、主题切换、页面跳转及底部设置可达性。
- 移动端筛选条件在列表和导出请求间一致，清除后 URL 同步更新。
- 深色主题下首屏告警、长消息和有数据的运营表格。

回归建立时先复现了金额折行、快捷入口截断、卡片裁切、分页溢出、排行键盘无响应、失败误报正常和抽屉底部设置不可见，再完成修复。

运行命令（在 `web/` 目录）：

```sh
npm run test -- src/components/AppNavigation.test.tsx src/components/admin/AdminPagination.test.tsx src/pages/admin/LogsPage.test.tsx src/pages/admin/AdminLanguageSync.test.tsx
npx tsc --noEmit -p tsconfig.app.json
npm run lint
npm run test:e2e -- layout-regression.spec.ts --project=chrome --workers=1 --reporter=line
```

浏览器检查使用本地 Vite 开发服务。模拟数据覆盖布局与交互，不代表线上业务数据或生产后端联调。本次未修改后端契约、未生成发布产物、未部署。

最终结果：17 项相关单元测试、10 项浏览器回归测试全部通过；TypeScript 类型检查、ESLint 和 `git diff --check` 通过。已人工复核桌面仪表盘、运营总览和移动导航截图。
