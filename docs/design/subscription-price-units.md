# 订阅售价与钱包金额

订阅套餐按人民币定价。`price_quota` 保留历史字段名，值为整数人民币元；支付宝订单仍以 `price_quota × 100` 计算人民币分。日、周、月额度与用量仍是美元额度，与套餐售价的单位不同。

钱包金额采用 `1 USD = 10000 amount`。钱包购买与立即升级的正差价按服务端 `RECHARGE_AMOUNT_MULTIPLIER` 换算，与充值一致：

```
钱包扣款 amount = round(人民币元 × RECHARGE_AMOUNT_MULTIPLIER × 10000)
```

默认倍率为 10。100 元套餐对应支付宝支付 100 元，或钱包扣除 10,000,000 amount（$1000 额度）。后台与用户页面显示人民币售价；目录中的 `wallet_price_amount` 是服务端计算的钱包等值金额，前端不使用构建时倍率推算订阅扣款。

`identity-service`、`admin-api`、`billing-service` 必须配置相同倍率。现有 Compose 文件已向三个服务注入同一环境变量。缺失或无效倍率使用与充值相同的默认值；金额过小或溢出时拒绝交易。

订阅 `PricePaid` 与变更请求中的旧、新价格继续表示人民币名义售价，保持历史套餐升级比较一致。正人民币差价才换算为本次实际钱包扣款。钱包余额、账本及对外变更结果记录固定精度的实际金额。历史订阅不回写、不补扣。

新支付订单在既有套餐快照中保存版本化 `price_conversion`，冻结当次充值倍率及钱包等值金额。退款仍采用现有的退到钱包政策，以实际支付的人民币分按冻结倍率换算；运行时改倍率不改变旧订单退款。旧快照没有该字段时保留其原退款计算，避免重新解释已付、已退款订单。退款执行、幂等返回与对账使用相同换算规则。

此修复不新增数据库迁移；部署须已应用现有迁移（包括保存订阅名义售价的 096 迁移）。上线应同时更新前端及 identity/admin/billing 服务，并核对各服务倍率一致；已创建的订单保留原快照。
