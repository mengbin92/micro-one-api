## 2. P0 — 凭证与启动配置安全

### 2.1 渠道凭证加密：先兼容迁移，后强制

当前读路径在解密失败时把值视为历史明文，因此可以兼容存量迁移；但写路径在未配置密钥或加密失败时继续写明文，必须关闭。

实施顺序：

1. **配置铺设**：将 `CHANNEL_ENCRYPTION_KEY` 加入 `.env.example`、Docker Compose、K8s Secret 与部署文档；启动时校验 AES key 长度只能为 16 / 24 / 32 字节。
2. **存量审计**：提供只读 dry-run，统计渠道 key、订阅账号 access token / refresh token 中可成功解密、疑似明文和不可判定的数量；输出只含计数与记录 ID，不输出凭证内容。
3. **幂等迁移**：对确认的明文记录加密回写；重复执行不得二次加密；执行前按部署规范备份数据库。
4. **写入收紧**：`encryptKey` 返回错误并向上层传播；密钥缺失、长度非法或 AES-GCM 失败时禁止写入，不再以“避免数据丢失”为由回退明文。
5. **启动强制**：使用持久化 channel 仓储时必须配置有效密钥；内存测试模式另行显式声明。

验收：

- [x] dry-run 与执行模式都有测试，输出不包含明文凭证；
- [x] 存量迁移可重复执行，迁移后所有目标字段均可用配置密钥解密；
- [x] 缺失 / 非法密钥时持久化 channel-service 启动失败；
- [x] 加密失败不会产生新明文记录；
- [x] Compose / K8s 配置校验与 channel data 测试通过。

### 2.2 DSN、JWT 与 Redis 降级策略

- 仿照 log-service 的 `LOG_MEMORY_MODE=true`，为 channel / identity 增加显式内存模式；未设置 DSN 且未显式开启时返回启动错误；
- identity 的 `JWT_SECRET_KEY` 缺失时不再随机生成进程级密钥；标准部署和直接启动使用相同的 fail-fast 语义；
- `TOKEN_HASH_KEY` 继续允许回退到已配置的 `JWT_SECRET_KEY`，但两者都缺失时只允许显式内存 / 测试模式，不使用公开固定值运行持久化服务；
- Redis 不作为所有服务的统一硬依赖：允许降级的路径记录结构化 Warn 与可观测状态；限流、幂等或事件语义要求 Redis 时再按功能 fail-fast。

验收：

- [x] channel / identity 缺 DSN 默认启动失败，显式 memory mode 仍可用于测试和本地开发；
- [x] identity 缺 JWT / token hash secret 的生产式启动失败；
- [x] Redis ping 失败不再静默，日志能区分“允许降级”和“功能不可用”；
- [x] 相关单测、Compose E2E 与 Release E2E 通过（本地验证及正式 v0.22.0 Release workflow 均通过，2026-08-19）。

## 3. P1 — API 契约与前端类型安全

### 3.1 修复 OpenAPI 生成链

当前 `make config` 与 `make api` 共用包含 `protoc-gen-openapi` 的模板。config-only 生成限制了 proto 路径，但仍运行 OpenAPI 插件，可能把根 `openapi.yaml` 覆盖为 `paths: {}`。

实施：

- 为 config-only 生成使用不含 OpenAPI 插件的独立模板或等价排除机制；
- 保持 `openapi.yaml` 为 ignored 临时生成物，并在文档中明确该策略，不恢复“既跟踪又忽略”的混合状态；
- CI 在安装生成器后执行 `make api-check`，确认规范非空且至少包含 `/v1/chat/completions`；
- CI 执行 `cd web && npm run generate:api`，随后用 Git diff 校验 `web/src/types/api.ts` 与 proto 同步；
- 选一个范围较小的页面 / API 模块试点引用生成类型，其余页面后续按触碰原则迁移。

验收：

- [x] `make config` 不创建或改写 `openapi.yaml`；
- [x] `make api-check` 生成的规范包含已注解 HTTP 路径；
- [x] 修改 proto 后不更新 `web/src/types/api.ts` 会被 CI 阻断；
- [x] 至少一个生产前端模块实际使用生成类型（通知面板复用生成的 NotificationItem 结构）。

### 3.2 TypeScript strict 与轻量 lint 收口

- [x] 在 `web/tsconfig.app.json` 开启 `strict: true`；
- [x] ESLint 增加 `no-console: warn`，清理现有少量生产 console；
- 不在同一 PR 顺带拆大页面、重做状态管理或批量调整格式。

验收：

```bash
cd web
npm run lint
npm test -- --run
npm run build
```

## 4. P1 / P2 — 小范围性能与可靠性修复

### 4.1 渠道模型映射批量化（P1）

- 为 `syncChannelModelMappingsTx` 补直接数据层测试，锁定 managed mapping 不覆盖手工 mapping、通配模型跳过和空集合删除语义；
- 批量解析 / 创建缺失模型，批量更新 managed rows，批量删除不再需要的 rows，使用 `CreateInBatches` 写入新增映射；
- 必须保持 MySQL / PostgreSQL / SQLite 方言兼容，不在 biz / service 层暴露 GORM 类型；
- 触碰 `app/channel/internal/data/data.go` 时可把 model mapping 持久化逻辑拆到同包独立文件，但不混拆其他 data 资源。

验收：行为测试通过；模型注册、managed mapping 更新/删除和新增 mapping 均使用批量查询/写入；channel 数据层测试通过。

### 4.2 Admin 批量删除完整性（P1）

- 将“固定 PageSize=1000 后删除”改为可证明完整的分页 / 游标循环；
- 补超过单页上限、部分删除失败、空集合三个回归用例；
- 触碰 admin HTTP 热点时只允许抽出 channel routes / handlers，不启动整个 admin god object 拆分。

验收：超过 1000 条禁用渠道时无静默遗漏；失败响应包含已处理数量；既有 OneAPI 兼容响应不变。

### P1 执行记录（2026-08-19）

- OpenAPI：新增不含 OpenAPI 插件的 `buf.gen.config.yaml`，`make config` 不再生成空规范；CI 增加 `make api-check` 和 `web/src/types/api.ts` 漂移检查。
- 前端：开启 TypeScript strict，加入 `no-console: warn`，通知面板使用生成的 API 类型并移除生产 console 输出。
- Channel：模型注册、managed mapping 更新/删除和新增 mapping 改为批量数据库操作，保留通配模型跳过和手工 mapping 不覆盖语义。
- Admin：禁用渠道清理改为反复读取第 1 页并排空，增加无进展保护，补充超过 1000 条、部分失败、空集合和列表不收敛回归测试。

### 4.3 请求体内存治理（P2）

- 建立端点分级：chat / messages / responses 等 JSON 请求采用较低上限；确有大载荷需求的 audio / image / raw 单独保留高上限；
- 读取 `limit+1` 或使用统一 body-limit 机制，确保超限返回 413，而不是把截断 JSON 误报为解析错误；
- 用并发内存基线或压测结果决定最终阈值，不把单一 10MB 值机械套用到全部端点。

执行结果：`/v1/chat/completions`、`/v1/messages`、`/v1/responses` 使用 8 MiB
JSON 上限（含 completions / embeddings / moderations / image generations /
audio speech）；multipart 音频、图片编辑/变体和 OneAPI raw proxy 使用 64 MiB
上限；超限在
`Content-Length` 预检或读取阶段统一返回 413。直接 handler 测试也使用“多读一字节”
检测，避免把超限截断 JSON 误报为 400。

### 4.4 前端通知与错误兜底（P2）

- `NotificationPanel` 改用 react-query 的 `refetchInterval`，删除手写 mountedRef / setInterval 请求状态；
- 增加全局 ErrorBoundary / route error element，验证页面渲染异常不会导致无提示白屏；
- localStorage 收口和大页面 schema 化继续按触碰原则，不与本项捆绑。

执行结果：`NotificationPanel` 使用 React Query 的 `refetchInterval`，查询错误展示
可重试状态；登录、受保护根路由配置 `RouteErrorFallback`，渲染异常提供重试和返回首页。

## 5. P2 — Relay 执行边界 ADR

本阶段完成决策并定义首个可验证切片；切片以独立 PR 灰度实施，不要求把
`internal/server` 全量迁移到 biz。

ADR 必须回答：

1. HTTP / gRPC 共用的 transport-neutral executor 输入、输出与端口接口是什么；
2. SSE、WebSocket、header 和响应写回如何留在 server，Plan / Reserve / Forward / Commit / Release / Log 如何复用；
3. adaptor registry 是否成为 server 唯一分发入口，以及 ProviderFactory 如何作为其底层实现保留；
4. relay orchestrator flag 的 staging → 默认开启 → 删除遗留路径时间表；
5. Chat Completions 首切片需要哪些等价测试、结算断言、failover 指标和回滚条件。

完成 ADR 后，仅在独立 PR 中迁移一个入口；观察稳定前不删除遗留路径，不同时搬迁 relay 目录。

ADR：[`v0.22-relay-execution-boundary-adr.md`](./v0.22-relay-execution-boundary-adr.md)。
本阶段完成决策文档；Chat Completions executor 首切片建立独立 PR、allowlist 灰度和
完整结算 / failover 对照后再迁移，当前默认路径不变。

## 6. 触发式事项（本阶段不主动实施）

| 事项 | 触发条件 |
|------|----------|
| admin / identity 全量热点拆分 | 对应子域再次发生实质业务修改；一次只拆一个域 |
| 公共 `ptr` / pagination / strings 工具包 | 至少有一个当前任务同时触碰两处重复实现，并能减少而非增加 API 面 |
| Dockerfile / Compose 全量收敛 | 下一次工具链或基础镜像升级，需要同时修改多份文件时 |
| relay-gateway 迁入 `app/relay` | executor 边界稳定、遗留路径删除后 |
| 登录限流迁 Redis | identity 多副本限流偏差出现证据或容量计划要求 |
| selector 状态跨副本共享 | 多副本路由统计失真达到可观测阈值 |
| 订阅 fail-open 改 fail-closed | 已具备错误率指标、告警和业务降级决策 |
| 表分区 / HPA / PDB / migration down | 延续 v0.21 的容量与运维触发条件 |

## 7. 推荐实施与发布顺序

1. 文档事实源切换（本文）；
2. 渠道加密配置、dry-run 与存量迁移能力；
3. 生产备份并执行迁移，确认凭证全部可解密；
4. 启用密钥 / DSN / JWT fail-fast；
5. 修复 OpenAPI 生成链、接入 CI 漂移门禁；
6. 开启 TypeScript strict；
7. 分别处理 N+1、Admin 批量删除、请求体和前端错误兜底；
8. 编写 Relay ADR，再决定是否在 v0.22 阶段实施首个迁移切片。

安全配置采用两个部署窗口：第一个窗口铺设密钥并完成兼容迁移，第二个窗口才启用强制启动校验。不得在生产仍存在未迁移明文记录时直接启用 fail-fast。
