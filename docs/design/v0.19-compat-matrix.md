# v0.19 协议兼容性契约矩阵

> 状态：v0.19 P1.1 已落地（2026-08-12）  
> 代码基线：`develop`（v0.18.2 之后）
> 关联决策：v0.18.2 web_search 修复、`internal/apicompat` 转换器、`internal/server` fallback 层

## 1. 目的

协议适配测试过去随具体 bug 生长（web_search 问题连续三个递进提交才根治），缺少一张统一的契约表。本矩阵把 Responses / Chat Completions / Anthropic / WebSocket 之间的转换路径显式坐标化，并让**新增 provider/tool/adaptor 路径时，未覆盖组合由测试直接失败暴露**，而不是等部署后才发现。

## 2. 契约矩阵

| 方向 | 入口/路径 | 流式 | 非流式 | tools/history 契约 | 错误/中断契约 | 守卫测试 |
|---|---|---|---|---|---|---|
| Responses → Anthropic | OAuth adaptor | 必测 | 必测 | web_search_call history 跳过；web_search/google_search/web_search_20250305 tool 丢弃；function tool 保留 | upstream 终止/断流 → 协议对应终态事件 | `internal/apicompat/compatibility_matrix_test.go` |
| Responses → Anthropic | API-key fallback | 必测 | 必测 | 同 OAuth；另剥掉 anthropic server-tool type 标识 | fallback 错误映射、SSE scanner/terminal | `internal/server/compatibility_matrix_test.go` + `responses_anthropic_fallback_test.go` |
| Anthropic → Responses | relay response | 必测 | 必测 | server_tool_use / web_search_tool_result block 静默跳过（SkippingBlock） | block 中断/半开 → 终态收敛；`max_tokens` → incomplete | `internal/apicompat/compatibility_matrix_test.go` |
| Chat Completions ↔ Responses | adaptor/fallback | 必测 | 必测 | assistant tool_calls ↔ function_call、tool result ↔ function_call_output 配对往返 | scanner/terminal event 合成（`transformChatCompletionStreamToResponses`） | `internal/apicompat` + `internal/server` 矩阵 + `token_usage_fixture_test.go` |
| WebSocket Responses | sticky/failover relay | 必测 | 不适用 | 终端事件驱动 turn 完成与计费提交 | graceful drain：healthz 503 + Retry-After、拒绝新 upgrade、连接关闭 | `internal/server/openai_ws_*_test.go` |

### 2.1 守卫测试的执行模型

矩阵以「注册表 + 覆盖断言」实现：

- `compatibilityMatrix`（apicompat）/ `serverCompatibilityMatrix`（server）是**唯一的契约表**，每个坐标带 `check func(t *testing.T)`。
- `TestCompatibilityMatrix_Coverage` / `TestServerCompatibilityMatrix_Coverage` 断言：
  1. `expectedMatrixCells` 中每个坐标都已注册且 check 非空；
  2. 注册表中没有不在期望清单里的孤儿坐标。
- **新增协议类型或 adaptor 路径**：必须在对应矩阵加 cell（否则 RunAllCells 不覆盖），并同步更新 `expectedMatrixCells`（否则 Coverage 失败）。两处都改动才会绿，缺失组合因此直接暴露。

## 3. Provider 专有 tool/block 的保留、转换、丢弃规则

### 3.1 请求方向（client → upstream）

| 输入类型 | Responses → Anthropic | Responses → Chat fallback |
|---|---|---|
| `function` tool | **保留**（转为 Anthropic tool，剥掉 type 字段） | **保留**（转为 chat tools） |
| `web_search` / `google_search` / `web_search_20250305` tool | **丢弃**（Kimi K3 / Zhipu / MiniMax 对 server tool 报 400；转发会触发 "Search results for query:" 无限累积） | **丢弃**（chat 无等价物） |
| history 中 `web_search_call` item | **跳过**（搜索已并入文本输出，回放无意义） | **跳过** |
| `reasoning.effort` | 映射 output_config + thinking（fallback 路径再剥掉，兼容 API-key 上游） | 忽略 |

### 3.2 响应方向（upstream → client）

| 输出类型 | Anthropic → Responses |
|---|---|
| `server_tool_use` block | **静默丢弃**（SkippingBlock 安全网；禁止转成 function_call / web_search_call 输出项） |
| `web_search_tool_result` block | **静默丢弃**（同上） |
| `tool_use` block（客户端工具） | **转换**为 `function_call` output item（call_id 双向往返编码） |
| `tool_result` block | 转换回 `function_call_output` |

### 3.3 不变式（已有专门断言，矩阵沿用）

- `assertChatInvariants`（`chatcompletions_responses_request_invariants_test.go`）：Chat 请求的 tool_calls 相邻性、禁止连续 assistant、孤儿 tool reply 丢弃、并行 tool calls 分组 —— 防止上游 400。
- `assertAnthropicPairing`（`responses_to_anthropic_tool_pairing_test.go`）：Anthropic tool_use 必须被下一条 tool_result 回答；孤儿 tool_result / 悬挂调用丢弃。
- 输出断言：矩阵 cell 对 `response.output_item.added` 断言 `type != function_call/web_search_call`（server-tool 被跳过而非转换）。

## 4. 扩展指引

新增 provider / tool / adaptor 路径时：

1. **改转换器**：`internal/apicompat/`（纯转换）或 `internal/server/responses_fallback.go`（fallback）。
2. **加共享 fixture**：`internal/apicompat/matrix_fixtures_test.go`（web_search / server_tool_use / tool round-trip 样例，多个路径共用同一契约形状）。
3. **注册矩阵 cell**：在所属包的矩阵表加行，`tools` / `errCase` 写明契约，`check` 写真实断言；更新 `expectedMatrixCells`。
4. **跑门禁**：
   ```bash
   go test ./internal/apicompat/... ./internal/server/... ./internal/adaptor/...
   ```
5. 若涉及流式/错误语义，参考 `internal/adaptor/oauth_adaptor_test.go`（premature-close / scanner-error / kimi-no-space SSE 回归）与 `internal/server/responses_anthropic_fallback_test.go`（v0.18.3 双路径契约对照）。

## 5. 覆盖边界（有意不做）

- 纯 pass-through handler 与 Wire/entrypoint 不追求矩阵覆盖（见规划 P1.4 边界）。
- 矩阵断言「契约行为」，不重复每个转换器的全部 fixture 细节；详细行为测试保留在原有专项测试文件中。
