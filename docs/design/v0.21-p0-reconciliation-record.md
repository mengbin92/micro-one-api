## 4. 发现：19 条迁移窗口孤儿账本（无 claim）— 已归因，风险低

**现象**：`billing_ledgers` LEFT JOIN claims 有 **19 条 ledger 无 claim**，全部集中在
2026-08-14 04:07:14 – 04:20:46（UTC），即迁移 `078` 应用（04:07:34 UTC）之后、
v0.20 billing-service 生效（04:21:03 UTC）之前约 **14 分钟窗口**：

```
26780–26798（19 条）  user_id=1  type=consume  ledger_dedupe_key='res_…:consume:subscription'
```

**归因**：迁移 `078` 的回填语句（`INSERT IGNORE … GROUP BY ledger_dedupe_key`）执行于
04:07:34 UTC；随后至 04:21:03 之间，**旧版本 billing-service（无 claim 写入逻辑）仍在
运行**，写入了这 19 条 consume ledger，claim 表未随之增长。04:21:03 起新写入 ledger 全部
有 claim（今日 309 条 ledger vs 290 条 claim，差额恰为 19）。

**风险评估（低）**：
- 这 19 条键为旧格式 `res_{reservation}_{ts}:consume:subscription`，与新格式
  `{action}:{user_id}:{request_id}`（purchase/topup）**天然不冲突**；
- `billing_ledgers` 唯一索引 `idx_ledger_dedupe_key` 当前仍存在（未分区），重复写入仍会被
  唯一索引拒绝——幂等闸门在该窗口内由唯一索引兜底；
- 全表 0 重复键，无资金重复扣减证据。

**闭环动作（✅ 2026-08-14 已完成）**：
1. ✅ **已补插 19 条孤儿 claim**：`INSERT IGNORE … LEFT JOIN … GROUP BY ledger_dedupe_key`
   （与迁移 `078` 同语义），执行后 `ledgers without claim = 0`、`claims without ledger = 0`、
   claims 26,879 = ledgers 26,879，补插行 created_at 与 ledger 完全一致；
2. ✅ **`checks.go` 已增加 claim 覆盖完整性检查**：新增 `checkClaimCoverage`（双向校验
   「ledger 无 claim」与「claim 无 ledger」），正路径 PASS、负路径（探针 claim）正确 FAIL，
   生产复跑 `RESULT: PASS`——孤儿账本现可被每次对账显式捕获；
3. 记录于 runbook：迁移与代码滚动部署之间应避免跨版本写入资金 ledger（可先停流/切维护
   窗口），或在迁移后立即完成 claim 存量回填一致性校验。
