## 2. 范围与成功标准

### 2.1 本阶段目标

- 并发相关的测试在 CI 中受 `-race` 守护,测试基础设施自身不再出现 data race。
- cache-creation charge 计费进入稳态:毛利/cache 价格异常可告警,对账可自动化执行。
- 发布门禁补完:强制失败验证有明确执行脚本与验收记录。
- 全仓库遗留 TODO 清零;BASELINE 基线有可对比数据。
- 性能热点(jsonx Marshal)有实测结论与明确的保留/优化决策。

### 2.2 非目标

- 不主动启动 P2.1(账号级会话窗口)、P2.2(负载感知排队)、#7 第二步——触发条件不满足。
- 不重启 grpc-gateway 迁移、log-service 组件化等暂缓项(重新评估条件见 §6)。
- 不新增微服务、消息中间件或计费数据库。
- 数据库变更保持 additive,不删除旧字段/旧列。

   - 落地:新增 `make test-race` 目标并接入 `.github/workflows/ci.yml`;本地
     `make test-race` 全绿(关联提交 `c5035fe`)。
2. **补齐 TODO 日志** ✅
   - `app/channel/internal/service/anthropic_model_probe.go:168` 的 `// TODO: add logging` 补结构化日志(失败原因、耗时),对齐相邻 probe 的日志风格。

### P1 — 运营闭环(charge 之后,约 2-3 人日)

1. **charge 后监控告警** ✅
   - 基于 `relay_token_usage_shadow_cost` / `billing_ledgers` 聚合,为以下场景增加 Prometheus 告警规则(或文档化查询):
     - cache-creation 计费桶毛利异常(负毛利、偏离供应商账单阈值);
     - 已路由但未定价模型(cache_creation 桶未配价)持续产生流量;
     - 观察成本与 charge 成本长期偏离(影子成本 vs 实扣)。
   - 管理端 `routing-ops` / 成本视图确认 charge 后展示正常。
   - 落地:新增 `micro_one_api_billing_ledger_gross_profit_quota` 指标与三条告警
     (`CacheCreationChargeUnpricedTraffic` / `CacheCreationChargeSignalLost` /
     `NegativeGrossMargin`);文档化 SQL 查询与验证步骤见监控 runbook;Grafana 新增
     3 个 charge 面板。
2. **对账周期自动化** ✅
   - 将 observe 阶段的手工核对脚本化为可重复执行的检查(ledger dedupe key、token 桶 vs 供应商账单、缓存命中率口径)。
   - 落点建议:`scripts/reconcile/` 下新增检查脚本 + 文档(README 说明用法与阈值)。
   - 验收:一次命令完成周期对账,输出差异报告;无差异时 exit 0。
   - 落地:`scripts/reconcile/reconcile.sh` + `scripts/reconcile/checks.go`
     (billing 全量对账触发、dedupe key、counted-but-unbilled、毛利、缓存命中率口径、
     供应商账单 CSV 对比),`README.md` 说明用法与阈值;无差异 exit 0。
3. **发布后强制失败验证(补完 §9.2)** ✅
   - 编写执行清单/脚本:强制一个普通渠道 + 一个订阅账号分别失败,确认:
     - dashboard/metrics 显示正确回退原因;
     - 最终 credential/usage/成本/账单只归属实际服务来源;
     - 账单只落一次(无重复扣费)。
   - 验收:验证步骤可复现,结论回写发布说明。
   - 落地:runbook(手工清单 + 等价 SQL)+ `scripts/verify-forced-failure.sh`
     (两场景自动禁用/回退/断言 metrics 与账本归属、单次计费)。

### P3 — 架构方向(中期议题,穿插推进)

1. **jsonx Marshal 性能决策**
   - 现状:`pkg/jsonx` benchmark 显示 sonic Unmarshal 快 2.3x,但 **Marshal 慢 2x**(312ns vs 150ns,Apple M5)。
   - 待办:在管理面响应序列化密集路径(admin-api/billing service)实测影响;若显著,评估 Marshal 路径回退 std(仅该函数)或配置调优。
   - 决策落档到 `docs/design/` 或 pkg/jsonx 注释,不反复摇摆。
2. **性能基线刷新**
   - 依据 `docs/design/BASELINE.md` 的 How to Run,在 v0.16 代码基线上重跑 k6 基线,填充剩余 TBD(P50/P95/P99、错误率、吞吐、缓存命中率、熔断状态)。
   - 与 Phase 0 基线(2026-07-17)对比,验证 v0.11–v0.16 观测增强未回退热路径。
3. **暂缓项重新评估**(仅当条件满足)
   - log-service 组件化:日志查询/持久化/批处理职责迁出且无远程调用方时再议。
   - grpc-gateway 迁移:出现独立 REST facade 需求时再议。
