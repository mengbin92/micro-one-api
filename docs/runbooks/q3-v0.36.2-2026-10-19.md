## 3. 区分跨版本成本与本版增量

- `v0.33.1` 至最近已发布的 `v0.36.1` 跨过多次功能与安全变更。`fd32cf2b` 已要求把客户端 IP 传到身份服务，并在带客户端 IP 时绕过旧的 token-only auth cache，以保证子网限制与撤权检查。该行为已有 `TestLegacyClientIPNeverUsesTokenOnlyCache`，本轮不恢复不安全的旧缓存。
- `/v1/models` 经 `availableModelsForRequest` → `getAuthSnapshot` → `getRawAuthSnapshot` → `CachedIdentityClient.GetAuthSnapshot` 走上述路径。该 handler、身份缓存和相关辅助代码在 `v0.36.1..候选` 中没有运行时改动。
- Q3 Compose 默认 `RELAY_REQUEST_TIMING_ENABLED=false`，本轮未覆盖该开关；新版计时 exporter 与 SQL 摘要分组写入不在此模型列表测量路径上。139 的普通日志索引成本仍由新旧正式版本的完整对照覆盖。
- 这些源码边界说明旧对照混入了此前已发布的成本，不能单凭旧基线报告把全部延迟归因于本版；它们不是精确性能归因或对旧退化的优化结论。没有通过删减授权检查来追平旧版。
