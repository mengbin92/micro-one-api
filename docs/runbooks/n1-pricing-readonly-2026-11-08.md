## 1. 范围与方法

- 从本地 `.env` 读取部署坐标，经 SSH 对生产 MySQL 执行 `REPEATABLE READ`、`WITH CONSISTENT SNAPSHOT, READ ONLY` 事务，结束用 `ROLLBACK`；单条查询上限 15 秒。只选价格、模型、映射及计费字段，不导出用户、Token、渠道凭据或请求正文。
- 主快照读取 16 个目录模型、13 条渠道映射、4 条订阅映射、11 条渠道 ability、5 条订阅 ability；正式 alias 和 `model_routings` 均为 0。核对渠道/账号模型列表、名称映射；补读 `restrict_models` 和网关磁盘上的全局模型映射。
- 近七天消费记录完整读取 2,971 行，低于 20,001 行的截断保护线。按 `reference_id + model_name` 合并请求；空引用以账本行独立分组。本窗无拆账，同为 2,971 请求。用户扣量取 `SUM(ABS(amount))`，采购估价取每请求 `MAX(upstream_cost)`，沿用现有对账脚本口径。
- 用不可变价格快照、五桶 usage 和倍率复算，不用当前价格重算历史。既有审计器明确镜像现行 float64 逐桶舍入和最低 1 quota；另用 Decimal 半入舍入检查精度边界。所有最近请求均为 `version=1 / verified / canonical`，快照关联齐全。
- 附加配置/监控读取与主快照分属不同时间；补读时五个价格/倍率选项的修订、更新时间和内容哈希均与主快照一致。未调用对账 POST、价格 owner 写接口或上游供应商，不触发付费请求，不修改历史账本。

依据代码：[历史审计舍入](../../scripts/reconcile/history-audit/audit.go)、[请求合并与毛利](../../scripts/reconcile/checks.go)、[正式路由与旧 ability 的优先级](../../app/channel/internal/data/data.go)、[未定价统计范围](../../app/channel/internal/biz/model.go)。生产库 `oneapi_billing.system_options` 是 VIEW，指向 owner 数据的读取面；“两边相同”不代表独立副本同步或真实三库验证。
