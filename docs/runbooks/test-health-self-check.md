# 测试自检

此自检确认少量关键断言能发现指定的生产代码回归，避免只凭 CI 全绿或测试文件数量判断测试有效。它不修改工作区里的业务源码，不连接生产服务。

## 运行

需要 Go 1.27.2、Python 3.9+ 和 C 编译器（SQLite 测试依赖 CGO）。首次检出先按正常测试流程执行 `make init proto`；之后：

```bash
make test-health
# 指定保留证据的位置；默认为系统临时目录下的独立 test-health-report-* 目录。
make test-health TEST_HEALTH_ARGS="--output-dir /tmp/test-health-review"
```

入口先运行自检脚本自身的单元测试，然后复制当前检出的文件（包含未提交修改、新文件和 Go 生成文件，排除其他忽略文件）。每个变异单独执行原版测试，确认通过后只修改临时副本，执行同一测试，再恢复副本。

## 首批四项

| 自检 | 故意制造的错误 | 现有断言 |
| --- | --- | --- |
| duplicate-purchase | 同一显式请求 ID 每次生成不同幂等键 | SQLite 事务路径中，8 次并发购买只能成功一次 |
| subscription-expiry | 反转订阅过期比较 | 固定注入时钟下，过期状态与到期提醒正确 |
| cache-read-cost | 将缓存读取费用置零 | 固定五桶用量下，缓存读取费用必须为 45056 |
| random-auto-key | 无请求 ID 时把随机自动键退化成常量 | 两次调用的自动键必须不同 |

输入和预期值沿用现有测试，没有在自检里重算一份生产算法作为答案。变异点和指定测试见 [scripts/test-health.py](../../scripts/test-health.py)。

## 判定与排查

- **通过**：每项基线测试确实运行且通过；变异版编译成功，由指定测试在预期断言位置失败，且 `go test` 退出码为 1。所有项都满足时入口才退出 0。
- **失败**：变异仍然通过、测试被删除/改名/跳过、源码锚点不再唯一、编译失败、panic、超时、其他测试失败或输出不完整，都不能算“错误被抓住”。Go 使用 `-count=1`，不复用测试结果缓存；单次测试限时 60 秒，含编译的命令限时 240 秒。
- **证据**：目录中的 `report.json` 保存变异前后片段、测试名和判定；`*-baseline.log` / `*-mutant.log` 保存命令与输出。先看基线，再看指定断言；正常重构导致锚点变化时，核对真实调用链后更新变异配置，不能简单删除自检项让流水线变绿。

[Test health 工作流](../../.github/workflows/test-health.yml) 每周一北京时间 11:00 调度，也支持手动触发。GitHub 定时任务在默认分支运行，工作流需合入默认分支后才生效；证据保留 30 天。普通 PR 不重复执行这组变异。

前端公共清理统一恢复 spies 和真实计时器；[setup.test.ts](../../web/src/test/setup.test.ts) 故意留下时钟、随机数与 fake timers，再确认下一例恢复原始全局对象。该测试随普通前端 CI 执行，本文件固定顺序，不依赖其他文件的执行顺序。

这四项不能证明所有 fixture 的业务含义都正确，也不替代真实链路、供应商证据或全量测试。新增真实漏检事故时，优先为它增加小而明确的变异；共享 fixture 的输入和预期仍需独立核对，避免同时改错。历史测试文件里的演示解析器也不能代替生产解析链路的回归测试。
