# 模型价格与上游成本后续工作

## 当前约定

- 用户价格以公开模型 ID 为键，并统一使用小写规范名，例如 `glm-5.2`。
- 同一个公开模型无论命中普通渠道、订阅账号还是其他供应商，都使用同一份 `ModelPrice` 售价。
- `GLM-5.2`、`glm-5.2` 和上游的 `z-ai/glm-5.2` 不应分别建立用户价格。
- 上游真实模型 ID 只用于路由映射，不出现在用户价格表。
- 线上 relay 使用 `BILLING_MODEL_SOURCE=requested`，账单按用户请求的公开模型名查询 `ModelPrice`。
- 未填写价格的模型不会写入 `ModelPrice`，价格页展示候选模型不等于已经启用收费。

## 后续事项

1. 清理模型库中的历史重复记录。目前线上同时存在 `GLM-5.2` 与 `glm-5.2`，需要把渠道映射、订阅映射、别名和统计数据迁移到 `glm-5.2` 后再删除重复记录。
2. 为模型表增加数据库级的规范 ID 约束或规范化唯一索引，阻止通过旧数据路径再次写入仅大小写不同的模型。
3. 增加独立的上游成本管理页面。配置键使用 `UpstreamModelPrice`，普通渠道可按 `<channel_id>:<upstream_model_id>` 精确配置，并保留按模型 ID 的默认成本。
4. 为订阅账号成本定义稳定的供应商维度键。当前上游成本代码以 `channel_id` 为区分维度，订阅账号需要避免与普通渠道 ID 混淆。
5. 在价格保存前显示未定价模型数量，并对已投入路由但没有 `ModelPrice` 的模型给出明确状态提示。
6. 增加计费回归用例：同一 `glm-5.2` 分别命中普通渠道、z.ai 订阅账号和 NVIDIA 渠道时，用户扣费一致，上游成本分别记录。
7. 价格正式录入后，对 `/v1/models` 返回值、计费日志 `model_name`、`ModelPrice` 键做一次线上一致性审计。

## 上线价格时的操作顺序

1. 在模型管理页确认目标模型为公开、启用状态，并至少有一个可用上游映射。
2. 在模型价格页只填写规范模型行，例如 `glm-5.2`，金额单位为 USD / 1M tokens。
3. 保存后检查系统选项中的 `ModelPrice`，确认键为小写公开模型 ID。
4. 使用小额测试账号分别调用各个上游路径，核对用户扣费、token 数和日志中的上游供应商。
5. 完成用户售价验证后，再单独录入和验证 `UpstreamModelPrice`，不要把采购成本当作用户售价。
