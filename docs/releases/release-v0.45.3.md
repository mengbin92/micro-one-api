# Micro-One API v0.45.3 发布公告

> 2026-11-18 · 上一版 [v0.45.2](./release-v0.45.2.md) · [GitHub Release](https://github.com/mengbin92/micro-one-api/releases/tag/v0.45.3)

v0.45.3 是 **PATCH 修复版本**。管理后台按资源契约读取写入版本，并处理渠道连续操作中的版本冲突。升级范围为 Web 静态产物。

## 1. 渠道连续操作等列表完成回读

**根因**。渠道测试会写入检测结果并推进资源版本。前端在测试后的列表回读期间仍允许启停，下一次请求可能携带旧版本。生产链路记录了一次测试成功、一次紧接的启用事务因版本冲突回滚及随后重试成功。

**修复**。渠道测试、刷新余额、启停、编辑和删除完成后等待渠道列表回读。管理端收到 409 时刷新对应资源查询，操作者可按刷新后的数据重新提交。

**影响服务**。管理后台 Web 渠道页及共用拦截器的管理写入。

## 2. 写入版本按资源归属和接口契约读取

**根因**。共享拦截器递归扫描缓存并按通用字段推断版本。相似的查询键和同值 ID 可能匹配到健康视图或关系对象。部分编辑表单提交时重新从列表取版本，路由组资源覆盖还需要字符串版本。

**修复**。按请求路径匹配属主缓存与版本字段。用户启停同时使用用户版本和策略版本，订阅账号编辑使用凭证版本，创建订阅账号时上游标识仅用于创建。模型映射使用模型版本，用户订阅使用权益版本。编辑草稿使用打开时的版本。路由组覆盖发送字符串版本，回读确认本次保存产生唯一版本增量后，同组其它已编辑行可继续保存。

**影响服务**。管理后台 Web 的订阅、模型和路由分组等管理页。

## 兼容性说明

- 沿用 v0.45.2 的 API、服务镜像和数据库结构。
- 服务端 CAS 继续拒绝过期草稿。客户端在冲突后回读资源，写入由操作者再次提交。

## 升级步骤

1. 构建并备份当前 Web 静态产物。
2. 上传新哈希资源，再原子替换 `index.html`。Admin 容器通过原目录挂载直接读取新产物。
3. 核对线上首页和本地主入口摘要，并检查首页、前端主脚本及 Admin 健康接口。
4. 用具有权限的管理会话验证一次渠道测试和启用，核对渠道属主审计与链路状态。

回滚时原子恢复备份中的 `index.html`，由原入口引用其对应静态资源。
