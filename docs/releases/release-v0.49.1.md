# Micro-One API v0.49.1 发布公告

> 2026-11-21 · 上一版：[v0.49.0](./release-v0.49.0.md) · [GitHub Release](https://github.com/mengbin92/micro-one-api/releases/tag/v0.49.1)

v0.49.1 是 **PATCH 修复版本**。Billing 修复 v0.49.0 在扣费已经提交后仍可能返回失败回执的问题。结算金额、订阅承担额和钱包承担额沿用现有接口字段，数据库沿用现有结构。 [v0.49.0 上线后离线复现记录](./release-v0.49.0.md#验证)

## 1. 从扣费事务取得同步回执

**根因**。v0.49.0 先提交扣费，再读取预留和消费流水以拼出同步回执。此时读连接故障，调用方会收到失败结果，钱包和账本却已完成结算。

**修复**。首次结算在扣费事务内记录本次实际的订阅和钱包分摊，事务提交成功后直接返回。流水写入失败或事务回滚时，调用方收到错误。相同预留重放时，Billing 使用已提交的状态和原有流水恢复回执。

**影响服务**。同步 `CommitQuota` 由 `billing-service` 提供。Relay 可按原预留标识重试。

## 2. 异步任务按已结算总额完成后续处理

异步 worker 与队列已满时的同步兜底使用同一结算入口。两条路径以实际总额执行后续额度上报，避免只为取得总额再读取分摊流水。异步受理与最终结算继续由原有回执状态区分。

## 兼容性说明

- 使用既有请求、回执字段、预留状态和流水去重键。本版不新增数据库迁移、运行开关或前端制品。
- 已提交的历史混合预留在两类分摊流水均未找到时，继续使用预留记录中受结算总额约束的估算。若预留状态暂时读不到、读取分摊流水失败，或已找到的分摊金额为负、合计与已提交总额不符，接口返回可重试的 `SETTLEMENT_RECEIPT_UNAVAILABLE`。确认预留不存在、已关闭或无权访问时沿用相应错误。

## 升级步骤

1. 保存当前 Billing 镜像和 Compose 回滚点，按部署流程更新 `billing-service`。 [部署手册](../deployment.md)
2. 核对容器状态与发布制品摘要，再用已有结算记录比对实际总额、订阅分摊和钱包分摊。
3. 需要回滚时，恢复上一版 Billing 镜像及 Compose 配置，保留已提交的预留、钱包和流水。v0.49.0 的提交后读故障仍可能影响回执。
