# Micro-One-API v0.39.2 发布：模型编辑价格直接发布与价格缓存刷新修复

> 2026-11-02 · 上一版：[v0.39.1](./release-v0.39.1.md)（2026-11-02）· [GitHub Release](https://github.com/mengbin92/micro-one-api/releases/tag/v0.39.2)

v0.39.2 是 v0.39.1 之后的 **PATCH 修复版本**：修复模型管理页已配置价格，但用户价格页仍缺少模型、必须到管理价格页再次保存才能生效的问题。模型新增或编辑成功后，admin-api 按单模型发布正式 `ModelPrice`，并刷新管理及公开价格缓存。无新增公开 API、数据库迁移或运行配置项。

本次修复已于 2026-11-02 更新生产 admin-api 和宿主机 Web dist，完成隔离模型的首次价格发布、编辑同步、数据清理及真实用户价格页检查。生产来源、回滚点与验收边界见 [部署验收记录](../runbooks/model-pricing-publish-production-2026-11-02.md)。本次发版不重复重启生产服务。

## 修复内容

### 1. 模型页保存价格后直接写入正式定价

**根因**：模型编辑仅保存注册表中的参考价格；管理价格页使用它预填，但实际计费及公开价格接口读取独立的 `ModelPrice`。预填展示让操作者误以为价格已发布。

**修复**：Admin 业务层将模型页的 USD/1M tokens 转成正式配置的 USD/token；存储层锁定同一价格配置并只合并目标模型，递增 revision，保留其他模型及缓存创建价格。按模型资源验证 `billing.pricing.update` 并记录事务审计，不要求操作者取得整张系统选项的写权限。无变化的参考价只补发缺失正式价格，不覆盖价格页独立维护的售价；`preserve_pricing` 明确保留受限价格。

显式清零保留零价标记，防止计费规范化后回退旧倍率；旧价格被脱敏时不使用脱敏零值判断“未变化”。发布失败不报告完整保存成功，返回安全的重试提示，不泄漏底层连接信息。

**影响服务**：`admin-api`。Billing 继续读取既有正式价格契约，无需更新 billing-service。

### 2. 保存后刷新公开价格及管理缓存

**根因**：模型变更仅刷新模型列表，已加载的用户价格页与管理价格配置仍可能使用旧缓存；部分成功的写请求也不会主动读回实际状态。

**修复**：模型变更刷新模型列表、详情、管理价格配置及 revision、摘要和公开价格缓存。新增与编辑请求失败时也回读缓存，保留错误提示，不显示成功提示；更新中英文说明，明确模型页保存会同步正式价格。

**影响服务**：宿主机独立部署的 Web dist，需与 admin-api 配套更新。

## 兼容性说明

- **API 与数据库**：无新增字段、端点或迁移；普通模型编辑新增正式价格发布行为，既有 ServiceTierPricing 优先规则保持不变。
- **直接 API 调用**：未设置 `preserve_pricing` 的模型更新会先读取详情，因此需要 `channel.model.read`。仅编辑资料且不读取价格的客户端应传 `preserve_pricing: true`；浏览器已有详情读取与价格可见性处理。
- **零值**：新建模型未填写任何价格仍不发布正式价格；清空已有价格按显式零价处理。
- **异常边界**：模型注册和正式价格由不同服务拥有，暂不具备跨服务原子事务。发布失败时模型信息可能已保存，应按错误提示在价格管理页重试；历史账单不回写。
- **部署**：无需新增环境变量或更新其他运行服务；保留现场计价开关和既有收费策略。

## 升级步骤

1. 获取 `v0.39.2`；已有环境无需数据库迁移。核对价格编辑账号具有相应模型及价格权限。
2. 在开发机交叉构建 Linux/amd64 admin-api，通过 `scripts/deploy-update.sh admin-api` 上传并部署，保留旧镜像；不得在生产服务器构建。
3. 在开发机运行 `cd web && npm run build`，单独备份并替换宿主机 `/opt/web/dist`。该路径通过只读挂载服务，单独替换镜像不会更新前端。
4. 检查模型页保存后的正式价格、用户 `/pricing` 展示和容器状态；发布失败按提示重试。2026-11-02 已完成生产更新的环境无需重复部署。

## 验证

- 完整 `make verify` 通过：格式、全量 Go 单元与 race、架构、迁移、RBAC/IAM、生成契约、Web lint、736 个前端测试、关键路径覆盖率及生产构建。

- 原始后端回归在修复前“模型库价格已保存、公开价格列表为空”，修复后通过，并断言实际计费配置写入正确。
- Admin biz/data/service/server 与 RBAC contract 测试通过，覆盖首次发布、参考价补发、独立售价保护、字段保留、权限范围、审计、并发、revision 冲突、脱敏清零及安全错误响应。SQLite 存储边界已验证；本地临时 MySQL/Postgres DSN 未配置的用例跳过。
- Billing 聚焦回归确认显式零价不会回退旧倍率。前端模型管理与管理/用户价格页共 41 个测试通过，包含保存后刷新及部分失败回读。
- 生产构建和资源体积检查通过；实际镜像/容器/本地来源摘要一致，宿主机与线上返回的前端入口哈希一致。
- 真实管理员浏览器创建非公开隔离验收模型，首次保存即写入正式价格，编辑后读回一致；随后清理验收模型和价格键并保留审计。用户价格页显示 `deepseek-v4.1-flash-1017` 的输入 $0.30、输出 $1.20、缓存读取 $0.006 / 1M tokens。未发起上游付费请求。
