# Micro-One-API v0.34.13 候选（发布中止）：鉴权、支付计费与分布式投递安全修复

> 2026-10-09 · 上一版：[v0.34.11](./release-v0.34.11.md)（2026-10-08）· [GitHub Release](https://github.com/mengbin92/micro-one-api/releases/tag/v0.34.13)

> **发布状态**：IAM 浏览器夹具已修复，但上一轮 Compose 结果确认初始化脚本仍写入明文渠道 key。本次流程主动取消，未生成正式 Release 或发布镜像，原 tag 保留。正式升级使用 [v0.34.14](./release-v0.34.14.md)，其中完整包含业务修复及两类验收夹具修复。

v0.34.13 是 v0.34.11 之后的 **PATCH 安全修复与发布恢复版本**。完整包含 v0.34.12 候选的业务修复，并修复 IAM 浏览器验收夹具；v0.34.12 因门禁失败未生成正式制品，原 tag 保留。统一不同调用路径的支付授权和账务核对，保护 IP 限制与 WebSocket 逐轮额度，修复账号恢复、凭据读取及分布式投递边界，并补齐前端会话和支付安全检查。

**无 API/proto 或数据库结构变更，无新增 DDL 迁移**。共享基础代码涉及九个主服务、已启用的 `channel-account-ops-worker` 和宿主机挂载的前端。既有 Token 哈希密钥必须保留，历史明文凭据必须先迁移，持久化 OAuth 会话及到期提醒去重需要 Redis。生产已于 2026-10-09 部署业务提交 `fd32cf2b`，本次补齐正式发布制品，无需重复部署。

## 修复与交付内容

### 1. 支付授权、对账与预留回收

**根因**：支付状态变更和资产发放未统一限制系统身份；对账可能依据不完整的供应商订单事实发放资产。供应商建单后的附加信息失败会丢失本地恢复线索，非原子回收可能与正常结算竞争。

**修复**：支付标记和资产发放入口校验系统身份，对账核对本地订单号及金额，附加信息失败时保留已创建订单。预留释放使用原子存储操作；过期权益不计入可用额度，续订保留既有权益事实。

**影响服务**：`billing-service`、`admin-api`，以及使用共享订阅库的服务。

### 2. Relay 逐轮授权与实际账号计费

**根因**：仅按令牌缓存鉴权会丢失客户端 IP；WebSocket 复用首次准入，后续轮次缺少独立校验和预留。故障切换后仍可能沿用初选账号或旧响应的用量事实。

**修复**：在 HTTP/RPC 边界保留客户端 IP，受 IP 限制的令牌使用新鲜鉴权；WebSocket 每轮重新鉴权并预留额度。普通渠道与订阅账号切换后，以实际执行账号和实际响应记录用量，保护租约所有权及过期边界。

**影响服务**：`relay-gateway`、`identity-service`、`channel-service`、`billing-service`。

### 3. 恢复证明、邮箱验证与凭据保护

**根因**：旧邮箱恢复路径缺少有效证明，邀请注册和 OAuth 邮箱验证边界不一致；OAuth 账号名冲突未通过真实 IAM 存储错误重试。Token 哈希缺少密钥时依赖固定默认值，凭据解密错误被当作明文继续使用。

**修复**：恢复要求有效证明，邀请注册校验邮箱证明，OAuth 只使用已验证邮箱；存储边界将账号名冲突转为可重试的业务错误。公开注册、恢复、验证和 OAuth 入口限流，JWT 验证 issuer。Token 哈希必须有专用密钥或既有 JWT 密钥；凭据解密失败显式报错，禁止将损坏密文发送上游。

**影响服务**：`identity-service`、`channel-service`，以及使用共享鉴权代码的服务。

### 4. Redis 会话、提醒与可靠投递

**根因**：本地 OAuth 会话和提醒去重不能覆盖多副本；租约续期可能复活已过期的所有权；Stream 截断或失败处理可能丢失未完成消息，通知 I/O 未完整遵循取消与目标校验。

**修复**：持久化 OAuth 会话和提醒 claim 使用 Redis，续期核对有效租约所有权。Stream 保留消费组未读和 pending 消息，失败重试并进入死信处理；请求体／响应有界，通知发送遵循取消并校验目标和邮件头，补齐审计、outbox 及缓存边界回归。

**影响服务**：`channel-service`、`channel-account-ops-worker`、`notify-worker`、`monitor-worker`、`log-service`，以及使用共享事件／缓存基础代码的服务。

### 5. 前端操作与配置边界

**根因**：退出未完整清理本地会话，支付地址缺少协议检查，删除 Token 缺少明确确认；部分字段更新和缓存计数存在边界偏差。

**修复**：退出清理会话状态，购买／订单页面统一校验支付 URL，Token 删除使用确认交互并补齐文案。修复部分更新、状态校验、缓存统计及无 watcher 配置处理；刷新 Channel Wire 输出和 831 项 RBAC 入口事实。

**影响服务**：独立前端、`admin-api`、`channel-service`、`config-service`，以及使用共享中间件的服务。

### 6. IAM 浏览器夹具与正式发布恢复

**根因**：IAM 浏览器矩阵通过 SQL 直接写入明文渠道 key；本版凭据读取规则拒绝明文，导致允许访问的渠道列表返回 500，浏览器无法找到渠道。该路径此前仅在显式浏览器验收时执行。

**修复**：夹具使用现有 AES-GCM 工具和 owner 测试密钥加密，保留真实 HTTP → gRPC → SQL 路径及权限／秘密负例。启动浏览器前增加真实渠道列表 HTTP 200 预检，将夹具错误收窄为约一秒的失败信号。完整矩阵本地 10 项通过、无跳过，结果契约检查通过。

**影响服务**：测试与发布文档；不修改生产运行时，不需要重复部署。

## 兼容性说明

- HTTP/RPC、proto 与数据库结构不变；更严格的授权、恢复证明、邮箱验证、IP、状态和输入校验会拒绝此前错误放行的请求。
- 保留当前 `TOKEN_HASH_KEY`；未单独配置时继续使用既有 `JWT_SECRET_KEY`。本次升级不要顺带更换哈希密钥，否则旧 Token 无法匹配。曾依赖固定默认值的环境需先制定既有 Token 的迁移／重新签发计划。
- `CHANNEL_ENCRYPTION_KEY` 继续使用原密钥。配置密钥后，任何解密失败均报错；历史明文先按[凭据迁移手册](../deployment.md#82-渠道凭证加密存量迁移v022)处理，损坏或密钥不匹配的记录不能盲目重写。
- 持久化存储环境的 OAuth 会话和到期提醒去重需要可用 Redis；公共入口限流依赖存储实现，失败时拒绝请求。多副本需连接同一 Redis，并保持既有服务身份与 IAM 配置。
- Stream 为保护未完成消息可能超过目标长度，需关注 pending、重试／死信及 Redis 容量。
- 前端继续由 `/opt/web/dist` 独立挂载；仅替换管理服务镜像不会更新前端。

## 升级步骤

1. 获取 v0.34.13，备份数据库、当前镜像、Compose、密钥配置与前端；保留 IAM、订阅和 executor 灰度开关。
2. 确认既有 JWT／Token 哈希密钥、渠道 AES 密钥和 Redis。使用 `channel-credentials` 默认 dry-run 检查凭据；有历史明文时先确认数据库备份，再显式迁移并复查。生产本次检查为 2 条渠道、3 条订阅账号均已加密，无需数据迁移。
3. 在本地交叉构建 linux/amd64，按身份、计费、渠道、管理、配置、日志、监控、通知、网关顺序更新九个主服务；禁止在生产服务器构建。已启用账号治理分片时同步更新渠道 worker，保持既有分片编号与任务开关。
4. 独立执行 `cd web && npm run build`，备份并发布宿主机 dist，先同步资源再替换首页，核对文件摘要及公网入口。生产已完成本版等价业务部署，无需为发布文档重复重启。
5. 核对实际镜像／源码摘要、health、重启次数、启动日志、公开状态接口和未登录鉴权；关注 OAuth、提醒、事件 pending 与死信。业务验证在受控环境执行，避免无意发送真实通知或创建支付。
6. 回滚使用保存的镜像、Compose 和前端目录，保持数据库与密钥一致；渠道分片回滚遵循[账号治理手册](../runbooks/subscription-account-ops-runbook.md)的停扫顺序。生产镜像回滚标记为 `rollback-20261009-105701`，前端备份为 `/opt/web/dist.bak.20261009-110445-fd32cf2b`；回退旧代码会重新暴露本版修复的安全问题。
