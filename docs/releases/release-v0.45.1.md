# Micro-One API v0.45.1 发布：订阅管理前端修复

> 2026-11-17 · 上一版：[v0.45.0](./release-v0.45.0.md) · [GitHub Release](https://github.com/mengbin92/micro-one-api/releases/tag/v0.45.1)

本版为 **PATCH 修复版本**：只改 Web 前端（`web/src`），无 Go 服务、无 API 契约、无数据库迁移变更。修复管理侧订阅操作的两个可用性缺陷——连续管理写复用陈旧 policy CAS 版本导致 409、额度策略相关表单的盲选与冗余输入——并把订阅额度策略归位到「用户与产品」，移除已失效的平台选择器。管理侧授权边界、计费语义与后端行为零变化。

## 1. 管理写后重新校验授权版本

**根因**：管理写请求携带的 `expected_policy_revision` 取自缓存的授权快照，而任何一次成功的 IAM 写都会推进全局 policy 版本（A3 契约）。写成功后前端从不刷新快照，连续操作（如批量禁用用户）时后续请求仍携带旧版本，被服务端 CAS 拒绝并返回 `authorization changed; reload and preview again`。表现为"一次成功、一次冲突"交替出现。

**修复**：写成功后与 409 冲突后都触发一次轻量的授权快照重校验——只 reset 授权查询，不中止在途请求。区别于 403/401 身份变更路径使用的 `refreshAuthorization()`（会 abort 所有受保护请求），普通的版本推进不应打断无关并发请求。重校验保留已校验的展示数据，同时识别序列化的 IAM CAS token，并将只读预览的成功响应与被替换会话的迟到响应排除在外。

**影响服务**：admin（Web 前端）。后端 CAS 逻辑未放宽。

## 2. 订阅额度策略归位与平台字段废弃

**根因**：订阅额度策略（quota policy）是面向用户的商品配额配置，却与渠道、路由分组一同挂在「资源与路由」下，与订阅套餐、用户订阅分离。同时其 `platform` 字段是额度策略与上游适配目标耦合时代的历史残留：relay 现已同时支持 OpenAI 与 Claude 协议，该字段不参与计费、配额或路由决策，只被存储并回显。

**修复**：额度策略移到「用户与产品」，位于订阅套餐与用户订阅之间。移除表格「平台」列与表单平台选择器及过时文案；编辑提交仍保留存量 platform 值，避免保存时把历史数据清空。桌面与移动端的导航与往返行为已覆盖测试。

**影响服务**：admin（Web 前端）。`subscription_groups.platform` 列与其 API 字段保留，仅从界面隐藏，便于确认无运营依赖后再单独迁移删除。

## 3. 订阅分配与套餐编辑的可用性修复

**根因**：手动分配订阅时到期时间必须人工计算填写，而所选额度策略本身已有 `duration_days`，重复且易算错；套餐编辑器要求手填额度策略 ID，管理员看不到该策略的额度上限，还可能把套餐从既有策略上清空或选中不可见的策略。

**修复**：选择额度策略后按 `duration_days` 自动填充到期时间，仍允许手工改成非标准期限（如赠送试用）；策略按名称选择并即时显示日/周/月额度（无限额显式标注）；保留当前绑定在可见列表之外的策略，避免编辑时被静默清除。表单校验、手工覆盖期限与最终请求体均有测试覆盖。

**影响服务**：admin（Web 前端）。

## 兼容性说明

- 无 Go 服务变更、无 proto/API 契约变更、无数据库迁移；不需要迁移或服务重启。
- 前端产物为静态资源，由 admin 只读挂载实时生效，无需重启容器。
- 管理侧授权校验（CAS）保持原样，本次只修正客户端刷新时机，不放宽服务端安全边界。
- `subscription_groups.platform` 字段在数据库与 API 中继续存在，仅前端隐藏。

## 升级步骤

1. 从 `.env` 读取部署目标，备份当前前端产物目录（`/opt/web/dist`）。
2. 本机构建前端（`npm run build`），打包后上传替换；产物为只读挂载，无需重启容器。
3. 校验 `index.html` 摘要与资源数量，确认新 bundle 被正确 serve（首页 200）。
4. 浏览器侧确认：连续两次管理写不再出现 409 交替冲突；分配订阅选择额度策略后到期时间自动填充；套餐编辑器可按名称选择策略并看到额度上限。
5. 验证通过后走 develop → main → tag。

**回滚**：恢复备份的前端产物目录即可，无数据或 schema 回滚需求。
